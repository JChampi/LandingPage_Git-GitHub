SNAPSHOT INMUTABLE

Anatomía de un Commit

Cada commit guarda un hash SHA único, un puntero a su commit padre, los datos del autor y una fotografía comprimida del proyecto. Por eso navegar por la historia es instantáneo.

GITHUB FLOW

Ramas limpias y Pull Requests

Mantén main siempre desplegable. Crea una rama por cada tarea, sube tus commits, recibe revisión en un Pull Request y fusiona cuando todas las pruebas pasen.

COLABORACIÓN REMOTA

Sincronización distribuida

Cada persona posee una copia íntegra del repositorio en su equipo. GitHub actúa como punto de encuentro para sincronizar cambios, ejecutar tests automáticos y revisar código.

Preparación del entorno

Requisitos antes de comenzar

Marca cada requisito conforme lo tengas listo. Tu progreso se guarda automáticamente en este navegador.

0 de 4 completados

1. Tener Git instalado (v2.30+)

CLI oficial de control de versiones

Instala Git según tu sistema operativo y verifica la instalación ejecutando git --version en tu terminal.

PowerShell / Winget 
winget install --id Git.Git -e --source winget
git --version

2. Cuenta de GitHub y autenticación

SSH o GitHub CLI (gh)

GitHub ya no acepta contraseñas en la terminal. Usa una llave SSH Ed25519 o inicia sesión en segundos con gh auth login.

Generar llave SSH 
ssh-keygen -t ed25519 -C "tu@email.com"
ssh -T git@github.com

3. Editor de código y terminal moderna

VS Code + Git Bash / PowerShell / Zsh

Configura VS Code como editor predeterminado de Git para evitar quedarte atrapado en Vim al escribir mensajes de merge o rebase.

Configurar editor por defecto 
git config --global core.editor "code --wait"
git config --global init.defaultBranch main

4. Identidad de autor configurada

Nombre y correo vinculados a GitHub

Cada commit guarda tu nombre y correo. Usa el mismo email de tu cuenta de GitHub para que tus contribuciones aparezcan en tu perfil.

Verificar configuración global 
git config --global --list

01

Configuración inicial (solo la primera vez)

Setup global

Define quién eres para que Git firme tus commits, fija main como rama principal moderna y activa la autocorrección de saltos de línea.

bash • configuración global 
# 1. Configura tu nombre y correo
git config --global user.name "Ana García"
git config --global user.email "ana@ejemplo.dev"

# 2. Establece 'main' como rama inicial y colorea la salida
git config --global init.defaultBranch main
git config --global color.ui auto
02

Iniciar un proyecto nuevo o clonar uno existente

Inicio

Si empiezas desde cero, crea la carpeta y ejecuta git init. Si vas a colaborar en un repositorio que ya existe en GitHub, usa git clone.

bash • opción A (nuevo) o B (clonar) 
# Opción A: Crear repositorio local desde cero
mkdir mi-proyecto-web && cd mi-proyecto-web
git init

# Opción B: Clonar un repositorio existente desde GitHub
git clone https://github.com/anagarcia-dev/mi-proyecto-web.git
cd mi-proyecto-web
Buena práctica: Crea un archivo .gitignore antes de tu primer commit para excluir node_modules/, archivos .env con contraseñas y archivos temporales del sistema.
03

Revisar cambios, preparar (stage) y hacer commit

Ciclo diario

Este es el ciclo que repetirás decenas de veces al día: inspecciona qué cambió, mueve al Staging Area los archivos listos y guarda una instantánea con un mensaje claro.

bash • status → diff → add → commit 
# Ver estado de archivos modificados y sin seguimiento
git status

# Ver línea por línea qué cambiaste antes de agregar
git diff

# Agregar un archivo puntual o todos los cambios
git add index.html
git add .

# Crear el commit con formato Conventional Commits
git commit -m "feat: agregar sección hero y barra de navegación"
04

Crear ramas para nuevas funcionalidades

Branching

Nunca desarrolles cambios grandes directamente sobre main. Crea una rama dedicada con git switch -c para experimentar con total seguridad.

bash • crear y navegar ramas 
# Crear una nueva rama y cambiarte a ella al instante
git switch -c feat/login-usuarios

# Listar ramas locales y ver en cuál estás (*)
git branch

# Ver el historial compacto con gráfico ASCII
git log --oneline --graph --decorate --all
05

Conectar con GitHub y sincronizar cambios

Remotos & GitHub

Vincula tu repositorio local con el remoto en GitHub (origin), sube tus commits con git push y mantente al día con el equipo usando git pull.

bash • remote, push y pull 
# Conectar repo local con GitHub (si usaste git init)
git remote add origin https://github.com/anagarcia-dev/mi-proyecto-web.git
git remote -v

# Subir rama por primera vez vinculando upstream (-u)
git push -u origin main

# Subir una rama de funcionalidad para abrir un Pull Request
git push -u origin feat/login-usuarios

# Traer los últimos cambios del equipo
git pull origin main
06

Fusionar ramas y deshacer errores sin pánico

Merge & Control

Cuando tu funcionalidad esté lista, intégrala en main con git merge. Y si necesitas pausar o deshacer cambios, usa stash, restore o revert.

bash • merge, stash y deshacer seguro 
# Volver a main e integrar la rama terminada
git switch main
git merge feat/login-usuarios
git branch -d feat/login-usuarios

# Guardar trabajo a medias temporalmente
git stash push -m "estilos en progreso"
git stash pop

# Deshacer un commit ya publicado de forma SEGURA
git revert HEAD
